# 英語読解の気持ちに関するアンケート

日本語母語の英語学習者向けの、HTML・CSS・JavaScriptだけで動く質問紙です。

公開URL：**https://ryuya-dot-com.github.io/Reading_Questionnaire/**

**現在は動作確認用の試作版（preview）です。本調査の参加募集は開始していません。**

- 読解不安：CMC-FLRASを基にした提供ドラフトの日本語23項目。
- 読解の楽しさ：提供ドラフトの新作9項目。妥当性は未検証。
- 母語（日本語）の読解7項目：楽しさ・関与3項目、不安4項目の探索用項目。
- 注意確認1項目、任意の氏名・学籍番号、学習背景6項目、日常の英語使用6項目、自由記述2項目。
- 説明・同意→背景→日常の英語使用→回答例→英語・日本語の気持ち40項目（1画面1項目）→自由記述→確認→CSV保存。
- 背景・日常の英語使用・自由記述は独立したセクションで順序固定。英語／日本語のブロック順と各言語内の項目だけを無作為化し、開始時の順番を見直し時にも保持。回答画面にPart A/Bや下位尺度名は表示しません。
- 画面数を基準にした全体の進捗バー。CSV作成後に100%となり、戻ると進捗も戻ります。
- 40項目の初回回答時間・累積アクティブ表示時間・表示回数・変更回数・計時中断回数を記録。背景・自由記述の個別時間は記録しません。
- 「データの使用を一切禁止しますか？」の「はい／いいえ」を開始前・完了前に用意。初期値は未選択。禁止時は氏名・学籍番号・回答内容を出力せず、利用不可の管理記録だけを保存。
- 保存前に氏名・学籍番号を確認でき、40項目を戻り直さずに修正できます。
- 1回答者1行のCSV。UTF-8 BOM、CRLF、引用符処理、自由記述の数式解釈防止。
- 回答完了操作でダウンロードを開始。再保存ボタンも用意。回答者がLMS等に提出します。

## 研究資料

- [文献レビュー・問いと調査設計・検証上の限界](docs/literature-review.md)
- [CSVのコードブックと全項目](docs/codebook.md)
- [実施した検証と未確認事項](docs/validation.md)

このサイトから回答を送信する処理はありません。研究者の端末にCSVが自動で集まる仕組みではありません。GitHub Pagesは静的配信です。LMS等で回収したファイルを機関の保管先で管理してください。回答データ、提供PDF、文献の全文を公開リポジトリに追加しないでください。

日常の英語使用は、資格試験（複数選択と得点等）、授業・課題外の読解頻度、週間読解時間、読む文章の種類（複数選択）、多読経験、英語圏への連続3か月以上の滞在経験です。自由記述は、英語学習で楽しかった／難しかった経験と、読解時の不安／楽しさを各2,000文字以内で尋ねます。未入力でも進めます。練習例「私は，夏より冬が好きだ。」はCSVにも得点にも含めません。

## 参加者向け画面と運用情報

画面は参加の判断と回答・保存に必要な案内に絞っています。「試作版を試す」、内部のCSV列名や計時方式、配信サービスの技術説明は表示しません。出典ページ `site/about.html` は残していますが、回答画面からのリンクは外しています。質問・選択肢、戻る／次へ、全体進捗を中心とした構成です。参加の判断に関わる収集対象は、氏名・学籍番号、回答内容、回答時間・操作記録として冒頭に短く案内します。

previewでも参加者向けの共通文言を表示します。運用モードは `site/config.js` とCSVの `data_mode` で確認してください。画面の文言を整理しても本調査には切り替わりません。動作確認には架空の氏名・学籍番号を使い、previewのCSVを本調査の回答として回収・分析しないでください。

40項目の提示順、初回回答時間・累積時間・表示回数・回答変更回数・計時中断回数をCSVに記録します。別タブ・ウィンドウへの移動中は項目の計時を止めます。計時の定義と制約は本README末尾とコードブックにまとめています。進捗は画面数に基づくもので、残り時間の予測ではありません。配信サービス・保存形式の説明も本READMEに記載しています。

## 手元で開く

`site/index.html` をブラウザで開けば動きます。ローカルサーバーを使う場合は：

```sh
python3 -m http.server 8000 --directory site --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8000/` を開きます。依存パッケージ、ビルド、APIキーは不要です。

## 他の研究者による利用と調査ごとの責任

共通の質問紙・画面と、個別調査の実施者情報を分けています。プラットフォーム提供者の氏名を全調査の責任者として表示する構成ではありません。共通の案内は「本調査の問い合わせ窓口」とし、本調査の開始画面・完了画面にはその調査の設定に基づく連絡先を表示します。

現行は1つの公開先に1つの調査設定を持つ静的サイトです。他の研究者が独立して実施する場合は、リポジトリをForkまたは複製し、別の公開先で `site/config.js` を設定します。`studyId` は調査ごとに異なる値にして、回収データが誤って結合されないようにします。共有URLの設定を書き換えて複数の異なる調査を同時運用する仕組みではありません。

個別調査では、参加者が実施者・所属・相談先を確認できる説明を用意します。責任者氏名の掲載方法や必要事項は実施機関の規程・承認された説明に合わせてください。この実装は本調査で `researcher`・`affiliation`・`contact` を必須とする設計を維持しています。これは全ての質問紙に共通する法的義務と断定したものではありません。機関が別途の説明文書等による案内を認める場合は、その実施方式に合わせて表示・設定を変更してください。

参考：[BPS Code of Human Research Ethics, Valid consent](https://explore.bps.org.uk/content/report-guideline/bpsrep.2021.inf180/chapter/bpsrep.2021.inf180.4) は、参加前の説明事項として責任者の氏名・連絡先等を挙げ、研究内容に応じた説明を求めています。BPSの指針を日本の全調査に一律に適用される法律として扱うものではありません。

## 本調査用の設定

`site/config.js` を編集します。初期状態は `mode: "preview"` で、試作CSVを `data_mode=preview` として出力します。

1. その調査の研究責任者 `researcher`、所属 `affiliation`、問い合わせ・撤回窓口 `contact` を記入。窓口には機関の研究用メールアドレス等も使えます。共通テンプレートの初期値は空欄です。
2. 実際の研究に即した倫理手続の説明 `ethicsStatement`、保管・利用方針 `retentionStatement`、提出後の撤回方法 `withdrawalStatement` を記入。承認を受けていないのに承認済みと記載しない。
3. 提出先の説明 `submissionInstructions` を確定。任意の `submissionUrl` にHTTPSのLMS・提出フォームURLを設定すると、完了画面にリンクが出ます。
4. 項目・教示・対象者・得点化と文献の利用条件を研究計画と照合。現在は18歳以上の説明・年齢選択肢なので、未成年を対象にする場合は画面や同意手続も変更。
5. 説明文・項目を変更したときは `consentVersion` / `instrumentVersion` を更新。`mode: "live"` に切り替える。必要な設定が空欄の場合、本調査の開始はブロックされます。

氏名・学籍番号は「あなたについて」で任意入力し、回答CSVの `participant_name`・`student_id` に保存します。無記名調査ではありません。LMS提出時にも提出者が分かる場合があります。研究者は回収後、分析用データから識別情報を分離し、必要な対応表は機関の保管方針に従って管理してください。回答はページ内のメモリだけに保存し、localStorage・Cookie・アクセス解析・外部フォントは使いません。再読み込みやタブ終了で未保存回答は消えます。サイト配信にはGitHub Pagesを使い、アクセス情報は配信サービス側で処理されます。回答CSVにIPアドレスやUser-Agentを追加する処理はありません。

説明文には「結果によって成績が下がらない」「参加・中止・利用禁止で不利益を受けない」「個人が特定される形式で公開しない」と記載しています。本調査では授業運営・回収方法・自由記述の引用方法もこの説明に合わせてください。説明・対象者の確認に加え、データ利用禁止の質問で「いいえ」を明示的に選んで開始する構成です。未選択を同意として扱いません。

## データの利用禁止

「はい」は利用禁止で `research_use_allowed=no`、「いいえ」は説明に従った研究利用を認める選択で `research_use_allowed=yes` です。二重否定の取り違えを減らすため、選択肢に意味を併記します。初回は選択せず、確認画面では開始時の選択を保持し、変更できます。

開始前に禁止を選んだ場合は、質問に答えることなく利用不可の記録を保存できます。完了前に禁止を選んだ場合も、入力済みの氏名・学籍番号・回答・自由記述・時刻・項目別計時・得点をCSVに含めず、保存後に回答内容をページのメモリから消去します。残すのは版、モード、ID、利用不可・同意状態の9列の管理情報だけです。残りの列は空欄です。

利用不可のCSVは `record_type=refusal`、`research_use_allowed=no` です。回収した場合は、下記の結合ツールで同じIDの過去回答よりも優先して除外します。研究結果の分析には使いません。**既に提出した原本・結合済みファイル・分析結果を自動削除する機能ではありません。** 研究者は撤回受付後、関連する保管先と分析データに対応を反映してください。別のセッションで開くと新しいIDになるため、提出後の撤回は元の回答IDを添えて研究責任者に連絡する運用が必要です。

## GitHub Pagesの公開

`.github/workflows/pages.yml` は `main` へのpushで、テスト後に **siteフォルダだけ** を公開します。GitHubの Settings → Pages → Build and deployment → Source は **GitHub Actions** を使用します。ルートの研究メモ・スクリプトをサイト配信に混ぜない構成です（公開リポジトリ内のドキュメント自体はGitHubで閲覧可能です）。

公開URLにプロジェクト名が含まれていても動くよう、CSS・JSは相対パスです。独自ドメインやサーバー契約は不要です。

## 回収CSVを結合する

個別CSVを `responses/raw/` に置き、入力フォルダ外に出力します。Python 3の標準ライブラリだけを使います。

```sh
python3 scripts/merge_csv.py responses/raw responses/combined.csv
```

試作版の動作確認CSVを結合する場合だけ `--include-preview` を追加します。

```sh
python3 scripts/merge_csv.py responses/raw responses/preview_combined.csv --include-preview
```

利用不可のCSVも同じ入力フォルダに置きます。読み込み順にかかわらず、そのIDの回答をすべて除外します。`--include-preview` を付けても利用禁止は解除されません。スキーマ2・3・4で利用意思が不明・矛盾しているCSVは停止して確認を求めます。

完全に同じID・内容の再ダウンロードは重複除去します。利用禁止IDを除外した後、同じIDで内容が違う場合や、版・モード・列構成が混在する場合は停止します。旧版のスキーマ1・2・3もそれぞれ単独では読めますが、異なるスキーマ・質問紙版とは混ぜられません。既存ファイルは上書きしません。提出前にCSVが編集されていても、結合出力時には列名・セルの数式に見える先頭文字へアポストロフィを付けます。既に対策済みの文字列へは重ねて付けません。このツールはデータの認証、別IDでの重複参加検出、欠測補完や尺度の妥当性検証を行いません。CSV内の得点は取り込み時に再計算することを推奨します。

## CSVと得点の扱い

現在は質問紙版 `2026-10-01.6`、CSVスキーマ4、301列です。資格試験と読む文章の複数選択は `|` 区切りで保存します。TOEIC合計点とReading点は別列、英検は合格級です。異なる試験を単一の得点に換算していません。

1〜5の数値と `NA`（経験がなく判断できない）、`SKIP`（回答しない）を区別します。欠測を0や3に変換しません。下位尺度が完全回答のときだけ平均を計算します。不安全体の合計点、検証済みではないenjoyment総得点、低・中・高の分類は生成しません。表示・記録される時間は質問紙への経過時間であって、英文の読解速度ではありません。

氏名と学籍番号は文字列として扱い、CSV内では学籍番号の先頭の0や英字を保持します。Excelは開き方によって数字だけの学籍番号を数値と推測するため、「データ→テキスト/CSVから」で **student_id列を文字列** に指定してください。BOMだけではExcelの型推測を防げません。氏名・学籍番号をファイル名やURLには含めません。

UTF-8 BOMを付けると通常のExcelで日本語を扱いやすくなります。地域設定によって列分割されない場合は、Excelの「データ→テキスト/CSVから」で **UTF-8・コンマ区切り** を指定してください。すべてのアプリ・端末での挙動を保証するものではありません。自動ダウンロードが保存の確認画面になるブラウザもあります。

## 母語項目・回答時間の解釈

日本語の7項目はPISAやRAT-Aの正式日本語版・検証済み短縮版ではありません。英語版とは項目内容・範囲が異なるため、総平均の単純な差を「英語特有の不安」としません。日本語の実際の読解能力も測っていません。採用根拠、対応する項目、追加候補は文献レビューに記載しています。

項目別の計時は、画面のDOM更新後から `performance.now()` で測ります。ページが表示され、ブラウザのウィンドウにフォーカスがある時間だけを加算します。初回回答までと見直しを含む累積時間を分け、進むボタンの操作や選択後の滞在も後者には含みます。残り時間を急がせるカウントダウンは表示しません。注意・眼球運動・読解速度を直接測るものではなく、画面内での離席・考え事・一部のOS休止等は区別できません。詳細な列定義と制約はコードブックを参照してください。
